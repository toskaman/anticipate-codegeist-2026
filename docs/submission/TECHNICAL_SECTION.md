# Devpost — "How we built it" (CORE input for the EXPERIENCE-owned submission text)

Updated 3 Nov 2026 from `docs/STATUS.md` (source of truth). ANTICIPATE is a Forge app (`global:fullPage` Custom UI + Node.js 24 resolvers, Forge KVS storage, a Rovo agent, a `rovo:mcp` module and a Jira workflow validator) built for Jira Cloud.

**Real Atlassian integration.** All user-initiated Jira reads and writes run `asUser()`, so Jira enforces the viewer's own permissions. The backend reads projects, JQL search, issues, issue links and components, and checks `mypermissions` right before any write. Every private operation requires an authenticated account; anonymous calls are refused.

**Evidence graph.** A bounded breadth-first crawler (depth ≤ 5, ≤ 200 nodes, cycle-safe) turns Jira links into a directed evidence graph. Every edge keeps its source link id, extractor, observation time and an epistemic status: `Blocks`/dependency links are CONFIRMED, `relates to` is INFERRED context only, and anything the user cannot read stays UNKNOWN, never assumed safe.

**Deterministic counterfactuals.** `packages/simulation-core` is a pure TypeScript engine. Each scenario (remove now, retain temporarily, migrate consumers first, or upgrade a dependency) is applied to an isolated copy of a frozen snapshot. Impacts are traced through reverse dependency edges with causal paths, and every result carries a reproducible hash. Upgrades distinguish breaking, declared-compatible and compatible-with-verified-test evidence: a compatibility claim without a confirmed test link raises an open question. Options are ranked by violations, then open questions. No probabilities or invented savings.

**Verified prevention.** Plans are read-only until a human approves specific actions. Approval is bound to the plan hash and the exact selection, is idempotent, and expires with the snapshot. Execution takes a per-plan lease, reconciles via marker labels/comments before any create (no duplicates after retries or lost responses), and reports VERIFIED only after re-reading Jira. A plan is COMPLETED only when every action was approved and verified; otherwise it is PARTIAL.

**Decision Firewall in Jira.** An opt-in Jira workflow validator gates issues labelled `anticipate-change`. A transition passes only with a decision attestation (schema 3) bound to the issue, plan hash, snapshot, a digest of the issue's links and a 14-day expiry. It refuses BLOCKED options, and refuses an option that only passes by assuming a migration Jira does not yet show (the change is re-simulated on live evidence without that assumption). New or removed links, or expiry, invalidate the attestation. Outage policy: Allow by default, Block selectable by Jira administrators only; an issue the app cannot read follows the same policy and is never treated as unlabelled.

**Prevention Passport.** An auditable record of the snapshot, compared alternatives, approvals, attempts, verified outcomes and open questions. It states whether the Jira transition is OPEN, CLOSED (with the reason) or NOT_GATED, and keeps minimized provenance after the snapshot expires.

**Rovo.** A Rovo agent (Decision Reviewer) and six read-only MCP tools (get evidence graph, simulate retirement, simulate dependency upgrade, simulate slip, get Passport, check plan freshness) expose the same deterministic engine to Rovo and external MCP clients. Rovo never approves or executes.

**Quality.** Shared zod 4 contracts validate every request and response (payload size capped). 80 backend tests (fake Jira: partial failure, retry, stale approval, expired snapshot, concurrency, cross-user access, partial-approval bypass, outage policy, and a 50-cycle soak test for idempotency, bounded storage and gate stability), plus contract and engine tests and 60 frontend unit tests. GitHub Actions CI on every PR. A 100-node, 3-scenario comparison runs in about 18 ms. Hosted acceptance on a real Jira site is recorded with dated evidence.

**Known limitations.** Plans are private to their creator (shared workspace is a design). Teamwork Graph is a prototype adapter, not wired in. `global:fullPage` and `rovo:mcp` are Preview modules. Cold start to a usable app takes about 8 to 11 s.
