## 2. Implemented in this pass

1. **"What kind of change are you planning?"** (Scenario Lab). Retire or decommission (existing scenarios, unchanged) / Upgrade a dependency (CORE's `upgradeScenarios`: A breaking upgrade now, B backward-compatible shim, C move consumers to the new version first). Decommission uses the retirement comparison; CORE's open-work policy (P4) applies to services automatically, so no separate fake journey was invented.
   - Upgrade is **disabled with an explanation** unless the backend advertises `scenario:UPGRADE_NODE` in `capabilities.operations` (CORE request R1). The UI never silently turns a retirement into an upgrade: switching kind discards the comparison.
   - Parity: a unit test imports CORE's `upgradeScenarios`/`standardScenarios` read-only and asserts the frontend request is identical.
2. **Named open questions** on each scenario card (reason badge + record name, first three, then "+n on Decision Firewall").
3. **Impact rows** say "Uses the changed record directly / Affected through another record · N hops from PAY-412".
4. **Settings → Use ANTICIPATE from Rovo**: agent name, the five read-only tools, and why approval/execution stay in the app. Worded conditionally ("depends on your site's Rovo access and administrator settings").

## 4. Interaction cost (counted, not timed)

- Existing Jira change: choose project → load candidates → choose candidate → Analyze = **4 interactions** to the dependency map.
- Blank site via guided demo: Start the guided demo → choose project → Preview → Create → Confirm → Analyze root = **6 interactions**. First-time creation takes ~15–20 s server side (CORE report); the UI states that and re-reads Jira instead of showing TIMEOUT.
- No local timing is claimed as hosted performance. Cold start (~20 s reported on hosted prod) is outside the frontend bundle: build output is main app JS 179.8 kB (47.0 kB gzip), lazy graph 193.8 kB (62.4 kB gzip), CSS 69.1 kB (12.7 kB gzip). The graph chunk loads only on Evidence Graph.

## 5. Accessibility findings

- axe WCAG 2.0/2.1/2.2 A–AA: no violations in the new tests (Scenario Lab upgrade journey, display menu, demo callout) — automated only.
- Change-kind options are a native radio group in a `fieldset`/`legend`; the unavailable option is disabled *and* described in text.
- Known gaps not covered by automation: native 200%/400% browser zoom, screen-reader walkthrough, touch-target audit on the graph controls. Not certified.
